# LollaNet Analysis Protocol

本协议规定任何 AI 如何在具体任务中调用 LollaNet。它是厂商无关的通用流程；宿主 Skill 或 Agent 只负责把这套流程适配到自身工具。

目标不是展示模型数量，而是让少量异质模型、私人长期上下文、反证和时间尺度检查实际改变当前任务的假设、预测或行动，并让使用过程可追踪、可质疑。

## 0. 先判断是否需要 LollaNet

以下任务默认直接完成，不启动多路召回：

- 简单事实查询；
- 格式转换、摘录或机械改写；
- 已有明确规格的低风险执行；
- 检索长期认知层不会改变结果的任务。

当任务包含重要取舍、高不确定性、竞争性解释、长期影响或不可逆风险时，执行完整协议。用户明确调用 LollaNet 时进入本协议，但若任务仍属于上述简单类型，则完成复杂度判断后跳过 Scout 并直接回答。

显式调用不意味着强行套模型。如果检索后没有模型能够改变判断，应说明“未发现有增量的模型”，然后直接回答。

## 1. 建模当前任务

先从当前环境建立一个临时任务模型，不写回长期层：

- 用户真正要判断、解释或完成什么；
- 已知事实及其来源；
- 用户明确给出的目标与约束；
- 当前假设、未知量和可能改变结论的信息；
- 风险、可逆性、时间窗口和利益相关者；
- 任务需要的是解释、预测、选择、行动还是复盘。

不要因为熟悉某个模型就把问题重述成该模型擅长回答的形式。先理解任务，再召回模型。

## 2. 选择最小私人上下文

私人信息不是每次分析的默认输入。只选择能显著改变当前判断的内容：

- 身份：相关经历、能力、资源和现实约束；
- 准则：与本次取舍直接相关的价值优先级；
- 长期目标：会改变当前方案排序的方向；
- 私人证据或模型覆盖：与问题机制直接相关的记录。

遵守以下规则：

1. 普通代码修复、格式处理等任务通常无需读取私人画像。
2. 不读取“也许有用”但不能说明判断影响的私人文件。
3. 不把读取到但未使用的信息带入 Scout 输出或最终回答。
4. 旧画像与用户当前明确表达冲突时，以当前表达为准并标记冲突。
5. 无法访问私人层时继续使用公共模型，明确缺少了哪类可能相关的上下文，不猜测用户身份。

## 3. 多路召回

复杂任务从三个互补方向检索。支持子 Agent 的宿主最多并行三个只读 Scout；不支持时按相同职责串行执行。

### 3.1 Model Route

搜索公共模型、相关的 `09-Cases/` 公开来源案例和必要的私人覆盖，重点匹配：

- `AI 调用条件` 与当前任务信号；
- `适用边界`、`不应调用` 和 `失效条件`；
- 模型的 `conflicts`、`supersedes`、状态与版本；
- 能产生可区分预测或行动差异的关联模型。

公开案例只有在 `source_refs` 能支撑相关事实且 `as_of` 适合当前任务时才可作为证据；案例整理者的推断仍需独立检查。

不要只按标题或关键词命中，也不要因模型常用就自动选入。

### 3.2 Memory Route

只检索第 2 步已证明必要的私人上下文，包括身份、准则、长期目标、项目证据和私人模型补充。Memory Route 不得浏览与当前任务无关的私人材料来“寻找灵感”。

### 3.3 Challenge Route

主动搜索：

- 对主解释不利的反证；
- 能解释同一事实的竞争性机制；
- 被忽略的利益相关者、基础概率或选择偏差；
- 短期收益造成的长期代价；
- 不可逆损失、尾部风险和模型失效条件；
- 与历史类比不一致的时代条件。

Challenge Route 的目标不是机械反对，而是找到会改变结论的证据或条件。

优先检索 `09-Cases/` 中具备可回引来源的支持案例、失败案例和反例；旧案例必须继续接受第 7 节的时代条件检查。

## 4. 统一召回契约

每个 Route 返回若干 Retrieval Packet。字段必须完整：

```yaml
kind: <model | memory | evidence | challenge>
title: <条目标题>
location: <文件路径 + 章节，或外部 URL + 定位信息>
source_category: <public-model | private-model | private-identity | private-principle | private-project | private-evidence | public-evidence | external>
match_signal: <为什么与当前任务相关>
basis: <底层来源实际支持什么>
boundary_or_counterevidence: <适用边界、冲突或反证>
as_of: <YYYY-MM-DD 或 unknown>
confidence: <low | medium | high>
```

Packet 是可审计的检索结果，不是新的证据层：

- `basis` 必须能回引 `location` 中实际支撑它的最窄章节或外部定位；依据来自子章节时，只有文档标题的定位不合格；
- Scout 的概括、置信度和彼此共识不能替代证据；
- 找不到来源时，标为低置信度的待验证线索；
- 来源过期时保留 `as_of`，不把旧状态写成当前事实；
- 私人来源只披露完成判断所必需的摘要和定位。

## 5. 去重、关系与冲突分析

把所有 Packet 合并后执行以下筛选：

1. 删除只换名称但解释机制相同的重复模型。
2. 删除不能改变假设、预测或行动的装饰性模型。
3. 合并同一底层来源产生的重复证据，不把重复召回当作独立支持。
4. 检查模型的冲突、替代、包含和因果上下游关系。
5. 复杂任务保留 3–7 个具有互补增量的模型；如果只有少于 3 个模型有可靠依据，明确报告召回不足且不凑数；超过 7 个时优先保留可区分预测最强的模型。

不得通过模型数量、多数票或固定系数综合结论。模型冲突时，比较：

- 各自声称的机制；
- 支持证据与反证；
- 适用和失效条件；
- 能区分它们的未来观察；
- 在不同条件下各自导出的行动。

`contested` 模型可以被召回，但必须与重要争议一起呈现。`deprecated` 模型默认不参与综合，除非用于历史比较或解释模型演化。

## 6. 基础概率与证据检查

在形成结论前检查：

- 是否存在可比事件的基础概率，样本是否真的可比；
- 当前证据是原始观察、可靠二手来源、个人记录还是 Agent 推断；
- 是否混淆相关、因果和叙事解释；
- 是否存在幸存者偏差、选择偏差、测量变化或样本过小；
- 哪个未知量最可能反转结论；
- 是否有小概率但不可承受的损失。

没有可靠基础概率时，明确写“不足以估计”，不要用伪精确数字填充。基础概率与当前特定证据冲突时，说明更新方向和理由，而不是自动服从任何一方。

## 7. 多时间尺度与历史类比

根据任务选择具体窗口，并至少区分：

- 即时影响；
- 阶段性反馈、适应和二阶效应；
- 长期路径依赖、复利、能力变化和不可逆后果。

时间窗口不能机械固定为某几个数字；产品实验、职业选择和制度变化需要不同尺度。

使用历史作为证据或类比时，必须比较：

1. 底层因果机制是否相同；
2. 制度、权力与治理结构是否可比；
3. 技术、信息传播和测量条件发生了什么变化；
4. 激励、资源约束和参与者构成是否可比；
5. 哪些时代差异会使旧结果无法迁移。

只具有叙事或表面相似性的历史案例可以启发问题，不能直接支撑预测。

## 8. 综合并自然回答

回答结构由当前任务决定。可以是一段建议、一份比较、一篇分析、代码变更说明或行动清单；不要固定输出十二个章节，也不要按模型逐个写摘要。

综合时：

- 给出当前最佳判断及其成立条件；
- 在会影响理解时区分事实、推断和建议，无需制造固定版式；
- 解释最关键的机制冲突、反证和不确定性；
- 给出能够区分竞争性解释的可观察信号；
- 让下一步行动与可逆性、信息价值和长期后果一致；
- 不为迎合用户准则而扭曲事实，也不把 AI 临时观点伪装成用户模型。

主回答之后可附简短“召回说明”，只列出实际影响结论的模型、私人上下文类别和底层来源。不要暴露未使用的私人信息或内部 Scout 对话。

## 9. 可选的认知修改提案

分析可能发现模型需要变化。允许建议的类型只有：

- `new`
- `amend`
- `split`
- `merge`
- `contest`
- `deprecate`

提案必须说明触发来源、支持证据、反证、时代条件、目标模型和预期影响。默认只在回答中展示，不自动创建文件，也不直接修改正式模型。

只有用户明确批准“记录提案”后，才写入 `private/model-proposals/proposed/`。只有后续状态为 `accepted` 的提案，才能创建 `candidate` 模型、递增已有模型版本或改变模型状态。记录提案与接受修改是两个独立授权动作。

## 10. 结束前自检

完成复杂分析前确认：

- 模型是否真的改变了假设、预测或行动；
- 是否把重复召回错误地当成多份证据；
- 是否正面处理了最强反证和模型冲突；
- 是否检查了基础概率、证据质量和多个时间尺度；
- 历史类比是否比较了机制与时代条件；
- 是否只读取和披露了最小私人上下文；
- 结论是否说明关键条件与可验证信号；
- 是否避免自动保存任务或修改长期认知资产。

如果某项无法完成，明确说明缺口及其对结论置信度的影响。LollaNet 帮助人扩大和校验判断，不替代人的最终选择。
