# LollaNet Analysis Protocol

本协议规定任何 AI 如何在具体任务中调用 LollaNet。它是厂商无关的通用流程；宿主 Skill 或 Agent 只负责把这套流程适配到自身工具。

目标不是展示模型数量，而是让少量异质模型、私人长期上下文、反证和时间尺度检查实际改变当前任务的假设、预测或行动，并通过芒格式双轨分析分别检查外部事实与判断形成过程，让使用过程可追踪、可质疑。

## 0. 先判断是否需要 LollaNet

以下任务默认直接完成，不启动多路召回：

- 简单事实查询；
- 格式转换、摘录或机械改写；
- 已有明确规格的低风险执行；
- 检索长期认知层不会改变结果的任务。

当任务包含重要取舍、高不确定性、竞争性解释、长期影响或不可逆风险时，执行完整协议。用户明确调用 LollaNet 时进入本协议，但若任务仍属于上述简单类型，则完成复杂度判断后跳过 Scout 并直接回答。

显式调用不意味着强行套模型。如果检索后没有模型能够改变判断，应说明“未发现有增量的模型”，然后直接回答。

## 1. 建模当前任务

先从当前环境建立一个临时任务模型，不写回长期层：

- 用户真正要判断、解释或完成什么；
- 已知事实及其来源；
- 用户明确给出的目标与约束；
- 当前假设、未知量和可能改变结论的信息；
- 风险、可逆性、时间窗口和利益相关者；
- 任务需要的是解释、预测、选择、行动还是复盘。

如果用户、建议者、组织或 Agent 已经提出暂定结论，同时记录：结论是什么、由谁提出、主要依据是什么、提出者与结论有什么利益关系，以及问题如何被表述。没有暂定结论时不要为了启动心理检查而虚构一个。

不要因为熟悉某个模型就把问题重述成该模型擅长回答的形式。先理解任务，再召回模型。

### 1.1 分析模式

在检索前区分复杂任务属于哪一种模式。模式只决定先后顺序，不降低证据、隐私、反证或双轨分析要求。

- **收敛判断模式**：目标、对象、约束、候选行动和成功标准已足以比较；任务是解释、预测、选择、行动或复盘。按第 3 至第 9 节检索、去重后保留 3–7 个有增量的模型。
- **发散—收敛探索模式**：用户提出的是模糊、新颖、尚未定型的创意、项目、产品、研究方向或媒介直觉；核心用户、价值、对象、交互、成功标准或问题本体仍不稳定。先用不同机制生成竞争性命题，再由用户或证据收敛。

若下列信号中至少两项成立，进入发散—收敛探索模式：

1. 用户询问“这是什么”“有没有意思”“如何创新”或尚未确定项目定义；
2. 核心用户、作品/交付物、价值、约束或成功标准缺失；
3. 同一想法可被解释为多个彼此不可互换的问题；
4. 当前表述被单一技术、平台或流行叙事锚定；
5. Agent 无法说明该体验、产品或研究为何必须依赖所称媒介，而不是现有替代方式。

模式不确定时，先进行最小发散，而不是把暂定表述当作既定项目定义。简单任务仍按第 0 节直接完成。

## 2. 选择最小私人上下文

私人信息不是每次分析的默认输入。只选择能显著改变当前判断的内容，并保持不同资产的语义边界：

- 身份：相关经历、能力、资源和现实约束；
- 价值函数：用户明确认可的终极价值、硬约束和未解决张力；
- 准则：在特定条件下如何行动的用户规则；
- 长期目标：服务某些价值、但可以被替换的目标状态；
- 当前焦点：已经获批的短周期资源配置和实验；
- 私人证据或模型覆盖：与问题机制直接相关的记录。

遵守以下规则：

1. 普通代码修复、格式处理等任务通常无需读取私人画像。
2. 不读取“也许有用”但不能说明判断影响的私人文件。
3. 不把读取到但未使用的信息带入 Scout 输出或最终回答。
4. 旧画像与用户当前明确表达冲突时，以当前表达为准并标记冲突。
5. 无法访问私人层时继续使用公共模型，明确缺少了哪类可能相关的上下文，不猜测用户身份。
6. 观察记录和重复行为只能作为自我理解的证据，不能自动升级为正式身份、价值、准则或目标。
7. 不把价值函数压成永久的全局权重。只有用户在具体情境中明确给出时，才使用临时阈值、优先级或权重。

## 3. 多路召回

复杂任务从三个互补方向检索。支持子 Agent 的宿主最多并行三个只读 Scout；不支持时按相同职责串行执行。

### 3.1 Model Route

搜索公共模型、相关的 `09-Cases/` 公开来源案例和必要的私人覆盖，重点匹配：

- `AI 调用条件` 与当前任务信号；
- `适用边界`、`不应调用` 和 `失效条件`；
- 模型的 `conflicts`、`supersedes`、状态与版本；
- 能产生可区分预测或行动差异的关联模型。

公开案例只有在 `source_refs` 能支撑相关事实且 `as_of` 适合当前任务时才可作为证据；案例整理者的推断仍需独立检查。

不要只按标题或关键词命中，也不要因模型常用就自动选入。发散—收敛探索模式中，Model Route 先返回候选透镜而不是最终方案：候选池通常为 8–12 张卡，覆盖至少四类不同机制，并至少包含一个会挑战当前问题表述的反向或竞争性候选。学科标签本身不是配额；若多个模型只是同一机制的换名，保留其中一个。

### 3.2 Memory Route

只检索第 2 步已证明必要的私人上下文，包括身份、价值函数、准则、长期目标、当前焦点、项目证据和私人模型补充。Memory Route 不得浏览与当前任务无关的私人材料来“寻找灵感”，也不得用 `observations/` 中的 AI 推断覆盖用户确认的正式资产。

### 3.3 Challenge Route

主动搜索：

- 对主解释不利的反证；
- 能解释同一事实的竞争性机制；
- 被忽略的利益相关者、基础概率或选择偏差；
- 暂定结论的形成是否出现可观察的激励、身份、承诺、权威、社会认同、可得性、措辞框架或置信度失准信号；
- Agent 是否受到用户措辞锚定、迎合倾向、检索材料显著性、熟悉模型或叙事连贯性的影响；
- 短期收益造成的长期代价；
- 不可逆损失、尾部风险和模型失效条件；
- 与历史类比不一致的时代条件。

Challenge Route 的目标不是机械反对或猜测他人动机，而是找到会改变结论的证据、条件或判断形成风险。心理影响只能作为待验证假设，并说明可观察触发信号、可能偏移方向、替代解释和区分方法。

优先检索 `09-Cases/` 中具备可回引来源的支持案例、失败案例和反例；旧案例必须继续接受第 7 节的时代条件检查。

## 4. 统一召回契约

每个 Route 返回若干 Retrieval Packet。字段必须完整：

```yaml
kind: <model | memory | evidence | challenge>
title: <条目标题>
location: <文件路径 + 章节，或外部 URL + 定位信息>
source_category: <public-model | private-model | private-identity | private-value | private-principle | private-goal | private-focus | private-project | private-evidence | public-evidence | external>
match_signal: <为什么与当前任务相关>
basis: <底层来源实际支持什么>
boundary_or_counterevidence: <适用边界、冲突或反证>
as_of: <YYYY-MM-DD 或 unknown>
confidence: <low | medium | high>
```

Packet 是可审计的检索结果，不是新的证据层：

- `basis` 必须能回引 `location` 中实际支撑它的最窄章节或外部定位；依据来自子章节时，只有文档标题的定位不合格；
- Scout 的概括、置信度和彼此共识不能替代证据；
- 找不到来源时，标为低置信度的待验证线索；
- 来源过期时保留 `as_of`，不把旧状态写成当前事实；
- 私人来源只披露完成判断所必需的摘要和定位。

## 5. 去重、关系、发散与收敛

把所有 Packet 合并后先执行以下共同筛选：

1. 删除只换名称但解释机制相同的重复模型。
2. 删除不能改变假设、预测、行动或问题表述的装饰性模型。
3. 合并同一底层来源产生的重复证据，不把重复召回当作独立支持。
4. 检查模型的冲突、替代、包含和因果上下游关系。

`contested` 模型可以被召回，但必须与重要争议一起呈现。`deprecated` 模型默认不参与综合，除非用于历史比较或解释模型演化。

### 5.1 发散—收敛探索

仅在第 1.1 节判定为发散—收敛探索模式时执行。目标不是把更多模型并入一个答案，而是检验当前问题表述是否过早锁定。

1. 从候选池中形成 3–5 个彼此竞争的项目、产品、研究或媒介命题；每个命题必须挑战一个隐含假设，并在核心用户、价值、交互机制、作品/交付物、问题本体或成功标准上与其他命题存在实质差异。
2. 对每个命题明确：触发模型或机制、它改变的假设、该命题下所称媒介为何不可替代、最小可证伪信号、最大失败模式，以及与其他命题不可兼容之处。
3. 不得把候选模型数、命题数或学科数当作支持强度，不得用多数票选择命题。
4. 用户或证据尚未选择命题时，不得把单一技术架构、MVP、执行路线或产品定位伪装成答案。可以给出有条件的下一步，但必须说明它依赖哪个未解决命题。
5. 不得为了发散额外读取私人资料或强行套用所有学科；找不到不同机制时，报告发散不足。

### 5.2 收敛选择与近期复用检查

收敛判断模式直接执行本节；发散—收敛探索模式只有在用户或证据选定暂定命题后才执行本节。

1. 复杂任务保留 3–7 个具有互补增量的模型；如果只有少于 3 个模型有可靠依据，明确报告召回不足且不凑数；超过 7 个时优先保留可区分预测最强的模型。
2. 每个保留模型必须说明：它改变了哪项假设、预测或行动；对项目/产品任务，还必须说明它改变的交互机制、MVP 范围或验证动作。
3. 若 Agent 在近期相关分析中重复调用同一模型，必须说明其这次带来的新变量或新行动增量；无法说明时不得仅因熟悉、常用或叙事完整而自动选入。
4. 发散阶段若候选池过度集中于同一类执行、效率或风险控制机制，补检索至少两类不同机制族的候选透镜；但不以学科配额代替机制相关性。

不得通过模型数量、多数票或固定系数综合结论。模型冲突时，比较：

- 各自声称的机制；
- 支持证据与反证；
- 适用和失效条件；
- 能区分它们的未来观察；
- 在不同条件下各自导出的行动。

## 6. 基础概率与证据检查

在形成结论前检查：

- 是否存在可比事件的基础概率，样本是否真的可比；
- 当前证据是原始观察、可靠二手来源、个人记录还是 Agent 推断；
- 是否混淆相关、因果和叙事解释；
- 是否存在幸存者偏差、选择偏差、测量变化或样本过小；
- 哪个未知量最可能反转结论；
- 是否有小概率但不可承受的损失。

没有可靠基础概率时，明确写“不足以估计”，不要用伪精确数字填充。基础概率与当前特定证据冲突时，说明更新方向和理由，而不是自动服从任何一方。

## 7. 多时间尺度与历史类比

根据任务选择具体窗口，并至少区分：

- 即时影响；
- 阶段性反馈、适应和二阶效应；
- 长期路径依赖、复利、能力变化和不可逆后果。

时间窗口不能机械固定为某几个数字；产品实验、职业选择和制度变化需要不同尺度。

使用历史作为证据或类比时，必须比较：

1. 底层因果机制是否相同；
2. 制度、权力与治理结构是否可比；
3. 技术、信息传播和测量条件发生了什么变化；
4. 激励、资源约束和参与者构成是否可比；
5. 哪些时代差异会使旧结果无法迁移。

只具有叙事或表面相似性的历史案例可以启发问题，不能直接支撑预测。

## 8. 芒格式双轨分析

复杂任务在形成最终判断前，对同一组已核验材料依次做两趟检查。双轨是两种分析视角，不是两个 Scout、两个独立 Agent 或两票表决。

### 8.1 理性分析轨

先从对象层判断哪些因素真正控制所涉及的利益与结果：

- 事实、利益相关者、收益归属和错误代价；
- 因果机制、基础概率、约束、机会成本和时间尺度；
- 当前证据支持什么、不能支持什么；
- 哪些可观察结果会验证、削弱或推翻暂定结论。

这一轨先产出对象层暂定判断，不因为第二轨发现了心理风险就预先改变事实标准。

### 8.2 心理误判审计轨

再从判断形成过程检查：用户、建议者、组织或 Agent 为什么会形成或接受这个暂定结论，哪些通常有用的自动心理倾向可能在当前情境中失灵。只检查具有任务信号并可能改变判断的倾向，不机械遍历偏见清单。

每个重要的心理误判假设必须说明：

- 可观察的触发信号，而不是对潜意识或人格的武断诊断；
- 它可能把证据搜索、解释、记忆、置信度或行动推向哪个方向；
- 专业信息差、合理启发式、价值分歧等替代解释；
- 能够区分这些解释的验证方法。

Agent 还必须检查自身是否受到问题措辞、对用户立场的迎合、上下文显著性、检索选择、熟悉模型、叙事完整感或置信度失准影响。Agent 不能直接观察人的潜意识，只能根据可观察过程提出有限度假设。

### 8.3 两轨合流

- 心理风险不是结论错误的证据；有偏移的过程可能偶然得到正确结论，过程合理也可能因信息不足而判断错误。
- 如果第二轨发现可能实质改变判断的风险，回到受影响的理性步骤，通过隐藏来源或利益、反向表述问题、寻找独立证据、预先规定更新规则等方法重跑检查。
- 比较重跑前后的结论、置信度和行动是否变化，并依据证据质量与因果适配形成最终判断，不让两轨投票。
- 第二轨没有发现增量时不强行罗列心理模型，也不必在最终回答中展示一份固定的偏见清单。

## 9. 综合并自然回答

回答结构由当前任务决定。可以是一段建议、一份比较、一篇分析、代码变更说明或行动清单；不要固定输出十二个章节，也不要按模型逐个写摘要。

综合时：

- 给出当前最佳判断及其成立条件；
- 在会影响理解时区分事实、推断和建议，无需制造固定版式；
- 解释最关键的机制冲突、反证和不确定性；
- 给出能够区分竞争性解释的可观察信号；
- 让下一步行动与可逆性、信息价值和长期后果一致；
- 不为迎合用户准则而扭曲事实，也不把 AI 临时观点伪装成用户模型。

主回答之后可附简短“召回说明”，只列出实际影响结论的模型、私人上下文类别和底层来源。不要暴露未使用的私人信息或内部 Scout 对话。

## 10. 可选：任务后的模型迭代

完成当前回答后，只有用户明确要求保存、复盘或检验本次重要任务、模型调用或外部输入时，才转入 [Model Evolution Protocol](Model%20Evolution%20Protocol.md)。

默认不保存任务记录；不得为此额外读取私人资料；不得自动创建 proposal 或修改任何正式模型、私人长期资产。该协议负责任务后的最小证据记录和复盘，本协议不重复其字段、模板或治理细节。

## 11. 可选的认知修改提案

分析可能发现模型需要变化。允许建议的类型只有：

- `new`
- `amend`
- `split`
- `merge`
- `contest`
- `deprecate`

提案必须说明触发来源、支持证据、反证、时代条件、目标模型和预期影响。默认只在回答中展示，不自动创建文件，也不直接修改正式模型。

只有用户明确批准“记录提案”后，才写入 `private/model-proposals/proposed/`。只有后续状态为 `accepted` 的提案，才能创建 `candidate` 模型、递增已有模型版本或改变模型状态。记录提案与接受修改是两个独立授权动作。

## 12. 结束前自检

完成复杂分析前确认：

- 是否正确区分收敛判断与发散—收敛探索模式；
- 探索模式是否先形成了彼此竞争的命题，而不是过早交付单一技术方案；
- 探索模式中的每个命题是否说明媒介不可替代性、可证伪信号和最大失败模式；
- 重复调用的模型是否说明了本次新的行动增量；
- 模型是否真的改变了假设、预测或行动；
- 是否把重复召回错误地当成多份证据；
- 是否正面处理了最强反证和模型冲突；

- 是否避免自动保存任务或修改长期认知资产。
