# Engineering Core Model Ablation Cases v2

本文件为四张工程学 active 卡提供第一波消融设计：每张工程模型在三个不同任务中测试。所有任务均引用 [benchmark-v2-task-matrix.md](benchmark-v2-task-matrix.md) 中的完全虚构场景；它不包含结果，也不预先认定 Full 条件应获胜。

每次运行必须遵守 [Model Test Protocol v2](../../07-Docs/model-test-protocol-v2.md)：Full 使用预先声明的 3–7 张非重复模型并包含目标卡；Ablation 完全保留该集合但移除目标卡；不得以近义模型或提示词暗中重建目标机制。使用 [model_ablation_record_template.md](../../03-Templates/model_ablation_record_template.md) 保存私有记录。

## A. 安全边际

- 目标卡：[`安全边际`](../../01-Models/学科知识/工程学/安全边际.md)
- ID / version：`mm-margin-of-safety` / `3`
- 测试任务：`A01` 数据中心制冷、`A02` 诊断设备环境验证、`A03` 基础设施维护预算。
- Full 条件应允许该卡改变的内容：把点预测转为载荷—能力—安全系数或缓冲区间；区分正常波动与尾部情景；给出压缩缓冲的触发条件。
- 评审的可区分检查：移除后，是否更容易只按平均预测配置；是否遗漏容量、资金或验证余量；行动阈值是否从条件性闸门退化为单次承诺。
- 反例检查：若后果可逆、负载已被高质量实时控制，或缓冲成本本身制造更大系统风险，Full 不应机械要求更大余量。

## B. 冗余

- 目标卡：[`冗余`](../../01-Models/学科知识/工程学/冗余.md)
- ID / version：`mm-redundancy` / `3`
- 测试任务：`A04` 供水传感器、`A05` 跨境客服连续性、`A06` 工资结算恢复。
- Full 条件应允许该卡改变的内容：区分数量冗余与独立冗余；识别电源、权限、部署位置、脚本和人员上的共因失效；要求切换与恢复演练。
- 评审的可区分检查：移除后，是否把双份组件或多次备份误当作可靠冗余；是否漏掉共同故障路径；是否没有恢复时间、切换责任和演练指标。
- 反例检查：若单点故障的损失很低、替代方案高度相关且成本过高，Full 应允许简化，而非把所有系统都做成 N+1。

## C. 瓶颈

- 目标卡：[`瓶颈`](../../01-Models/学科知识/工程学/瓶颈.md)
- ID / version：`mm-bottleneck` / `3`
- 测试任务：`A07` 制造热处理、`A08` 门诊化验审核、`A09` 视频法务审核。
- Full 条件应允许该卡改变的内容：先找制约吞吐的环节；度量流量、在制品和排队；避免在非瓶颈处增加资源；监测改善后的瓶颈迁移与返工。
- 评审的可区分检查：移除后，是否出现“所有环节一起提效”的泛化建议；是否遗漏队列、返工和在制品；是否没有把资源/实验优先投向当前约束。
- 反例检查：若需求而非能力才是主约束，或质量/安全是更高优先级约束，Full 不应仅追求吞吐。

## D. 反馈回路

- 目标卡：[`反馈回路`](../../01-Models/学科知识/工程学/反馈回路.md)
- ID / version：`mm-feedback-loop` / `3`
- 测试任务：`A10` 学习 App 打卡、`A11` 客服结单激励、`A12` 电网需求响应。
- Full 条件应允许该卡改变的内容：画出正/负反馈、增益、延迟和可能的振荡；避免对短期指标的直接强化；设计护栏、试验和稳定性观察。
- 评审的可区分检查：移除后，是否只给静态 KPI 建议；是否遗漏延迟副作用、反向激励或拥塞回弹；是否没有说明应监测的领先和滞后信号。
- 反例检查：若反馈强度很弱、延迟很短且有明确的外生约束，Full 不应把普通一次性因果误写成复杂闭环。

## 每个单元的共同判定

只有以下观察才可支持“目标卡具有独立行动增量”的谨慎结论：

1. Full 与 Ablation 在匿名评审中出现可解释的关键差异；
2. 差异落在目标卡所特有的机制、预测、风险或行动阈值上；
3. 该差异不能由同一 Full 集合中的另一张已声明模型完全解释；
4. 目标卡也通过了至少一个反例/不适用检查，而不是在所有任务中强行套用。

即使满足以上条件，结论仍限于所测任务分布；它不是自动升级、自动合并、自动淘汰或公共模型修订依据。
