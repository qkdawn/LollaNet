# 模型组合复盘清单

用于人工复盘一批用户选择保存的重要模型调用记录。它评估的是模型在具体任务中的独立增量与边界，不按调用次数、成功率或固定加权总分给模型排名，也不直接修改模型状态。

## 进入条件与隐私

- 是否只使用了用户选择保存的记录，而没有把未保存任务当作缺失或失败？
- 是否明确本次复盘范围、保存目的和相关的时间尺度？
- 是否避免披露或复制未使用的私人资料、原始聊天和项目材料？
- 是否将私人调用证据、公开来源和 Agent 推断分别标识？

## 独立行动增量

- 每个被讨论模型是否改变了至少一项假设、预测或行动？
- 如果不调用该模型，结论是否确实会不同？
- 是否把模型名称出现、重复表述或回答变长误当成模型增量？
- 是否存在更少模型即可覆盖相同行动含义的情况？

## 证据、预测区分度与边界

- 支持证据、最强反证、适用边界和未知量是否都可回溯？
- 是否提出了能区分竞争性解释的可观察预测或检查？
- 即时、30 天、90 天结果是否与原始条件性预测一致？
- 若结果不一致，是否区分模型错误、适用性错误、执行、环境与随机性？

## 组合结构

- 是否有两张或多张模型在机制、变量、边界和行动含义上高度重复，值得研究 `merge`？
- 是否存在不可调和的预测或行动冲突，值得研究 `contest`？
- 是否有低频但覆盖罕见高损失风险的模型，应保留而非因使用少被淘汰？
- 是否有模型长期无法提供独立行动增量，只是在复述另一个模型？

## 私人适配与公共模型边界

- 私人资料改变的是模型选择、参数、风险阈值或行动排序，而非公共机制吗？
- 是否把私人任务结果误写成公共模型事实或普遍证据？
- 对公共 `amend`、`merge`、`contest` 或 `deprecate`，是否另有公开、独立、可核验的证据？
- 是否避免从结果倒推用户价值函数、原则、长期目标或身份？

## 复盘结论

仅选择或展示以下人工审议建议；不得直接改变模型状态：

- [ ] 维持：保留现有模型与边界
- [ ] 继续观察：等待更多任务、反证或延迟复盘
- [ ] 继续研究：补充机制、来源、反例或适用条件
- [ ] 提案建议：展示 `new` / `amend` / `split` / `merge` / `contest` / `deprecate` 草案

> 模型状态变更仍只能通过既有 proposal 的记录、接受和正式修订流程完成。
