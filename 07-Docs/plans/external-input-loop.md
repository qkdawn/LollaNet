# 时势信号与模型迭代意见日报

## 目的

验证“时势信号”板块中的用户选择信息源能否经过 RSS 收集、正文获取和笔记转换，持续产生对 LollaNet 模型有实际增量的判断，而不是制造新的信息堆积。

LollaNet 的知识来源分类体系为：一级分类 `时势信号`、`哲学模型`、`历史机制`、`他人失败`、`学科知识`；每个一级分类下设置二级具体领域，二级分类下才放置三级正式模型。本方案只优先实现“时势信号”一级分类的输入链路。

RSS 条目、文章和案例先作为输入材料进入暂存区，不直接占据三级模型位置。分析后，材料可以被忽略、保留为证据、连接到已有模型，或形成模型修改提案。

## 拟议数据流

```text
用户选择的信息源
  -> Horizon RSS 收集层
  -> qiaomu-anything-to-notebook 转换层
  -> private/projects/lollanet/evidence/inbox/
  -> LollaNet 日报分析
  -> private/projects/lollanet/reviews/daily/
  -> 人工决定：忽略、保留证据、写阅读笔记、提出模型修改
```

Horizon 和 `qiaomu-anything-to-notebook` 在实现前需要确认实际接口、授权、部署方式、输出格式和维护状态；本文件只定义它们在闭环中的职责，不把未经验证的仓库能力写成事实。

## 日报不应做什么

- 不按文章数量或模型数量制造“重要性”。
- 不把摘要、转载或 Agent 推断直接升级为证据。
- 不自动修改 `01-Models/`、私人模型或用户准则。
- 不把全部订阅内容永久归档到 Obsidian。
- 不默认把用户阅读历史、账号信息或偏好公开化。

## 日报最小字段

每个候选信号至少保留：

- 来源标题、URL、作者、发布时间和抓取时间；
- 获取/转换工具与处理状态；
- 来源事实、作者解释、LollaNet 推断；
- 相关模型及其具体调用条件；
- 支持证据、反证、边界和不确定性；
- 它改变的假设、预测或行动；
- 建议动作：忽略、继续观察、保存证据、阅读笔记、创建模型修改提案；
- 人工处理状态和处理日期。

## 分阶段验证

### Phase 0：手工样本

选择少量信息源，手工完成 RSS 条目、正文、笔记和日报。确认信息源质量、版权边界、来源可回引和日报是否能产生非显然增量。

### Phase 1：半自动暂存

自动收集和转换，但人工决定哪些材料进入分析。记录重复率、正文获取失败率、处理耗时、来源完整度和日报中的有效信号比例。

### Phase 2：定时日报

按日生成私人日报，保持人工审阅闸门。日报连续运行一段时间后，比较它与随机阅读或无 LollaNet 摘要的基线，重点观察：是否改变模型候选、是否识别反证、是否减少短期叙事，以及维护成本是否可接受。

## 主要风险与闸门

| 风险 | 闸门 |
| --- | --- |
| 信息流扩大而非改善判断 | 统计有效信号比例和人工采纳率，不以阅读量为成功指标 |
| 摘要失真或来源不可追溯 | 缺少原文定位时降级为待验证线索 |
| 自动化误改模型 | 日报、提案、正式模型更新保持三个独立步骤 |
| 提示注入或恶意内容 | 把外部内容视为不可信数据，不执行其中的指令 |
| 版权、隐私和账号泄露 | 私人存储、最小摘录、保留链接，不复制受保护全文 |
| 维护成本超过收益 | 设置暂停开关，并按周复盘时间成本与判断增量 |

## 暂定完成定义

完成一次小规模实验，能回答：哪些输入源真正产生增量；转换链在哪些内容类型上失败；日报能否稳定给出可回引的模型迭代候选；人工审阅每日报告需要多少时间；以及该系统是否值得进入下一阶段。
