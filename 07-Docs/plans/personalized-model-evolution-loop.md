# 个人资料驱动的模型应用与迭代闭环

## 目的

把 LollaNet 的公共模型、私人长期资料和真实任务的结果反馈连接成可审计闭环，同时保持三者的语义与隐私边界：

```text
公共模型回答：世界通常如何运作？
私人资料回答：对这个人而言，哪些目标、代价与约束重要？
当前任务回答：在此时此地应如何行动？
迭代闭环回答：本次调用是否带来了可验证的决策增量？
```

本计划不主张缩减公共模型库。模型库可以保持必要的跨学科广度；每个复杂任务构造至少两套竞争机制程序，每套只使用 2–5 个具有独立机制作用且关系连通的模型。

这是一项未来能力设计，不代表当前已经实现，也不会自动创建任务记录、读取私人资料或修改任何模型卡。

## 系统定位

本计划属于“模型演化证据层”的**真实任务与私人适配通道**：它记录经用户选择保存的模型调用、最小私人上下文和延迟复盘如何形成审议线索。统一的手工证据记录、复盘与治理交接规则见 `04-Prompts/Model Evolution Protocol.md`；它不替代 `04-Prompts/LollaNet Analysis Protocol.md` 的任务级模型选择，也不替代 `PROJECT_SPEC.md` 第 8 节和 `private/model-proposals/` 的正式治理。

与之并列的“外部认知输入通道”由 `07-Docs/plans/external-input-loop.md` 处理公开材料、时势信号和阅读线索。两条通道可以分别触发 proposal，但私人任务材料不得自动进入公共证据链；公共模型修订仍需公开、可核验的独立证据。

## 问题与原则

公共模型的机制、公式、公开证据和适用边界不能因个人偏好而改变；但价值函数、原则、目标、当前焦点、资源和风险约束会影响模型是否应被选中、怎样参数化以及行动建议如何排序。

因此，个人资料必须接入模型的**应用、校准与结果评估**，而不是改写公共模型的因果机制。

| 层次 | 责任 | 不应做什么 |
| --- | --- | --- |
| 公共正式模型 | 通用机制、公式、来源、反例和边界 | 写入用户画像、真实任务或私人偏好 |
| 私人长期层 | 价值、原则、目标、焦点、私人约束和私人模型适配 | 把偏好伪装成公共事实 |
| 当前任务层 | 选择模型、解释任务条件、输出建议 | 默认沉淀任务全过程 |
| 私人评估层 | 保留用户选择保存的调用结果、反证与延迟复盘 | 自动修改正式资产 |
| 提案治理层 | 把稳定的演化理由转为可审议 proposal | 根据调用次数或单次结果自动升级/废弃模型 |

## 拟议数据流

```text
公共模型卡（机制、边界、公开证据）
                 +
最小且获授权的私人资料（目标、约束、原则、当前焦点）
                 +
当前任务环境（事实、资源、风险、时间）
                 ->
任务级绑定与竞争机制程序构造
                 ->
自然语言建议、条件性预测与可验证下一步
                 ->
用户选择是否保存私有调用证据
                 ->
即时 / 30 天 / 90 天复盘
                 ->
私人模型适配线索或模型修改提案
                 ->
人工审阅、接受后才 amend / merge / contest / deprecate
```

真实任务、用户资料、项目约束和复盘结果默认留在 `private/` 或原任务环境。只有独立、可公开核验的来源和经用户接受的提案，才能支撑公共模型的正式修订。

## 个人资料怎样影响分析

个人资料只能在与当前任务相关且用户明确允许时进入分析。它们的作用不同，不能被合并为单一用户分数：

| 私人资产 | 可以影响 | 不可以影响 |
| --- | --- | --- |
| Value Function | 目标权衡、可接受损失、资源排序 | 公共模型的真假或因果机制 |
| Principles | 行动否决条件和不可跨越边界 | 证据事实 |
| Long-term Goals | 时间尺度、阶段目标与机会成本 | 模型公式 |
| Current Focus | 短期优先级与注意力分配 | 永久模型状态 |
| Project Profile / 资源约束 | 方案可行性、参数范围、实施节奏 | 公共模型的适用边界声明 |
| 私人 observations | 待验证的个人使用线索 | 身份、价值、原则或目标的自动改写 |

例如，安全边际的 `M = C - L` 与 `FS = C / L` 保持不变；个人资料只可影响可承受后果、缓冲规模和可逆行动的选择。瓶颈的流量与排队机制保持不变；当前目标决定“系统吞吐量”以什么衡量。冗余和反馈回路同理：个人资料可以校准成本、风险、恢复能力和反馈频率，但不能改写可靠性或稳定性的基础机制。

## 任务级调用证据

未来新增的模板应只在用户决定保存时写入 `private/evaluations/` 或 `private/projects/<project_id>/reviews/`。最小记录应包括：

```markdown
## 任务与调用
- 任务与关键决策：
- 实际机制程序、模型绑定与关系：
- 每套程序改变的假设 / 预测 / 反事实 / 行动：
- 最强反证、边界或未知量：
- 可观察的验证信号：

## 个性化输入
- 实际使用的私人资料类型：价值函数 / 原则 / 长期目标 / 当前焦点 / 项目约束
- 资料引用或版本：
- 它如何改变模型选择、参数、阈值或行动优先级：
- 未使用哪些私人资料：

## 复盘
- 即时、30 天、90 天观察：
- 结果更可能归因于：模型机制 / 适用性 / 个人约束 / 执行或环境 / 未知
- 是否值得提出私人适配或模型修改提案：
```

记录只保存所需的最小抽象和引用，不复制完整个人档案；输出给用户时应说明本次建议因哪些已授权资料而不同于通用建议，但不得披露未使用的私人内容。

## 私人适配与公共模型演化的分界

对于公共模型 `mm-<id>`，未来可在 `private/models/` 维护少量私人适配，而不是复制出一套私人公共卡。私人适配可以记录：

- 对该用户在哪些条件下具有实际增量；
- 受价值、原则、资源或风险约束影响的参数范围；
- 已知误用模式、过度使用风险或个人反例；
- 指向私人项目、评估和复盘的最小引用；
- `candidate`、`active` 或 `contested` 等私人状态。

私人适配只能说明“对该用户何时怎样使用”；它本身不能证明公共模型普遍成立，也不能直接改写公共卡。真实任务的私人结果最多形成私人提案或待验证线索；公共 `amend`、`merge`、`contest` 或 `deprecate` 仍需满足现有 proposal 治理和公开证据要求。

## 多维复盘，不设自动总分

不得按调用数量、成功率或固定加权总分决定模型命运。低频模型可能覆盖罕见但高损失风险，不能因近期未调用而废弃。

模型组合复盘应分别审查：

| 维度 | 审查问题 |
| --- | --- |
| 独立行动增量 | 没有该模型时，假设、预测或行动是否不同？ |
| 预测区分度 | 是否形成可被后续事实区分的预测或检查？ |
| 证据质量 | 机制、来源、反例与适用边界是否可回引？ |
| 重复度 | 是否只是另一模型的换词版本？ |
| 冲突 | 是否与其他模型产生不可调和的预测或行动含义？ |
| 个体适配 | 是否因私人约束而改变了行动，还是模型机制本身改变？ |
| 长期结果 | 即时、阶段性和长期观察是否一致？ |

这些维度只产生审议线索，不能自动更新模型版本、状态、个人资料、价值函数、原则或长期目标。

## 风险与闸门

| 风险 | 闸门 |
| --- | --- |
| 个人资料被过度读取 | 任务相关性、明确授权、最小字段和引用级记录 |
| 将个人偏好误写成公共知识 | 公共卡不得包含真实用户资料；私人适配与公共模型分离 |
| 以结果倒推用户价值 | 观察只能挑战或形成提案，不能自动改写正式私人资产 |
| 用模型次数替代判断质量 | 不设自动总分；保留低频高价值模型 |
| 单次成败触发过度更新 | 至少区分模型、适用性、个人约束、执行与环境等归因假设 |
| Agent 静默改变长期资产 | 调用记录、proposal、接受与正式修改保持独立步骤 |
| 私人任务证据泄露 | 默认保存于 `private/`；公共修订仅使用可公开核验的独立来源 |

## 分阶段落地

### Phase 0：协议与模板

- 新增任务级模型调用与个性化评估模板；
- 新增模型组合复盘清单；
- 在分析协议中增加最小私人资料、使用说明和不保存默认值；
- 不创建任何自动记录，不修改现有模型卡。

### Phase 1：手工私有试运行

- 仅对用户选择保存的少量重要任务记录调用证据；
- 比较通用建议与个性化建议的差异；
- 在即时、30 天与 90 天复盘中记录反证、执行条件和归因不确定性；
- 检查记录成本是否低于获得的判断增量。

### Phase 2：模型组合审议

- 定期审查重复、冲突、低频关键风险和有稳定增量的模型；
- 将具有稳定理由的结论显示为 proposal，而不是自动变更；
- 对私人适配与公共模型修订使用不同证据标准。

### Phase 3：私有 Episode 复盘与提案支持

Phase 1–2 用于校验证据契约、隐私边界、归因质量和回滚条件；通过这些前置验证后，系统可以协助汇总获授权经验、比较事前预测与结果、整理归因假设、生成候选草案和验证清单。它仍不得自动接受、部署、回滚或改写模型版本、状态、个人资料、价值函数、原则或长期目标；这些动作继续遵循显式 Proposal 与用户授权。

## 暂定完成定义

完成一次小规模、可暂停的私有试运行，能够回答：

1. 哪些私人资料确实改变了模型选择或行动建议；
2. 个性化是否带来可解释的增量，而非仅增加叙述长度；
3. 哪些调用证据支持私人适配，哪些仅反映任务或执行偶然性；
4. 是否出现值得提出 `amend`、`merge`、`contest` 或 `deprecate` 的稳定理由；
5. 30/90 天复盘、隐私最小化与维护成本是否能够共同成立。

在这些问题得到验证前，本计划不得被描述为已实现的个性化模型迭代能力。
