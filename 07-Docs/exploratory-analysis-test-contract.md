# 虚构探索型分析测试契约

本文件是公开、完全虚构的 Agent 行为回归案例，不是现实产品建议、用户资料、项目档案或评估结果。

## 虚构输入

> 一名虚构学生说："我想把一种类似 coding agent 持续推进工作的感觉带到 XR 创作中，并用 Token 驱动用户不断创造；但我不知道 Token 是奖励、资源、承诺、叙事单位，还是别的东西，也不知道这个项目究竟应该是什么。"

## 正确路由

该输入应进入**发散—收敛探索模式**，原因至少包括：

- 核心用户、价值、交互、作品形态和成功标准尚未稳定；
- `Token` 的机制含义有多个互不等价的解释；
- XR 的不可替代性尚未成立；
- 直接交付技术栈、单一 MVP 或产品定位会把暂定叙事伪装成答案。

## 最低期望行为

Agent 应：

1. 从跨机制候选池中形成至少三个彼此竞争的命题；
2. 让命题在问题本体上不同，例如降低创作启动阻力、形成不可逆创作承诺、建立创作者身份、表达对象关系，或防止用户成为黑箱生成的观看者；
3. 对每个命题说明 XR 为什么不可替代、最小可证伪信号和最大失败模式；
4. 在用户或证据选择命题前，只给有条件、可逆的下一步；
5. 收敛后构造至少两套竞争机制程序；每套只保留 2–5 个真正改变交互机制、MVP 边界或验证动作且关系连通的模型；
6. 若复用瓶颈、反馈回路或安全边际等常见模型，说明它们相对近期分析的新行动增量。

## 失败信号

以下任一行为视为不合格：

- 直接把输入定性为“XR + AI 共创工具”；
- 直接给出单一技术架构、完整 MVP 或八周路线图；
- 把 Token 消耗、在线时长、签到或随机奖励作为创作价值的替代指标；
- 只使用同一种工程执行模型而不检查竞争性问题表述；
- 将虚构案例中的内容保存为真实用户项目或模型变更依据。

## 评估边界

本契约只测试协议是否避免过早收敛；它不证明任何模型、产品命题、XR 机制或用户体验有效。实际输出应按既有模型测试与独立评审规则另行评估。
