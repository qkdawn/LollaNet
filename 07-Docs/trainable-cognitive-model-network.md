# LollaNet 可训练认知模型网络架构

## 1. 定位

LollaNet 的目标不是把模型卡变成一个更复杂的规则引擎，也不是把“反馈回路”“安全边际”等语义全部压缩进不可解释的向量。目标形态是一个**语义锚定、数值可训练、由真实结果纠正的认知模型网络**：

> 人定义或确认认知模型的语义和接口；数据学习模型什么时候适用、应该连接谁、影响多大、以什么顺序运行，以及组合后是否真正改善预测和行动。

该网络借鉴神经网络的节点、连接、激活、抑制、路由、信用分配和可塑性，但保留每个认知模型的显式身份、机制、边界和可检验输出。它不要求所有计算端到端可微，也不把 Transformer 的 token 层和注意力矩阵当作架构边界。

本文件描述目标架构，不声称仓库当前已经实现训练器、自动语义演化或在线部署。公共产品边界仍以 `PROJECT_SPEC.md` 为权威。

### 1.1 四层总体结构

目标形态的 LollaNet 暂分为四层：

| 层 | 职责 | 主要内容 |
| --- | --- | --- |
| 任务状态层 | 表示当前任务和共享工作状态 | 情境、目标、观察、约束、未知量、不确定性和推理历史 |
| 能力算子层 | 决定当前执行哪一种认知操作 | 定义、解释、质疑、求证、创造、决策、学习 |
| 显式模型网络层 | 提供可组合、可检验的世界机制 | 模型身份、语义接口、条件性连接、结构化预测和行动信号 |
| 结果学习与演化层 | 用经验纠正网络 | Episode、误差归因、信用分配、数值训练、语义提案、测试和回滚 |

这四层不是四个依次执行的固定阶段。共享认知状态 $h_t$ 和可训练路由器贯穿各层：路由器可以选择一个能力作用于一个或多个显式模型，把结构化输出写回任务状态，再决定继续、回退、请求证据、形成行动或停止。结果学习与演化层跨 Episode 运行，并将数值更新或经验证的语义版本反馈给网络。

```text
任务、目标、观察和约束
  -> 共享任务状态
  -> 能力—模型联合路由
  -> 七类能力算子 × 显式模型网络
  -> 预测、反证、证据要求、方案或行动
  -> 写回共享状态并循环，或等待真实结果
  -> 数值训练与受治理的语义演化
```

## 2. 核心学习问题

LollaNet 真正要学习的是：

$$
\boxed{
\text{给定情境和目标，学习哪些显式模型应当以什么顺序、强度和结构共同工作}
}
$$

与此同时，网络还必须处理现有语义模型无法解释的稳定残差：

$$
\boxed{
\text{当现有显式模型持续留下结构性残差时，由语言模型提出语义演化，再由真实结果决定是否接受}
}
$$

第一项是连续、频繁的网络动力学学习；第二项是离散、低频的语义结构演化。两者必须分层运行，避免把路由错误、执行错误或随机结果误判为模型语义错误。

## 3. 网络表示

令网络的可计算核心为：

$$
\mathcal{N}=(V_C,V_M,E;\Phi,\Theta)
$$

并令：

$$
V=V_C\cup V_M,
\qquad
E=E_{CC}\cup E_{CM}\cup E_{MM}
$$

其中：

- $V_C$：七类能力算子节点，规定当前执行什么认知操作；
- $V_M$：具有稳定身份和接口的显式认知模型节点，规定使用什么机制思考；
- $E_{CC}$：能力之间的跳转、循环、回退和停止关系；
- $E_{CM}$：能力对模型的调用、组合、检验和更新信号关系；
- $E_{MM}$：显式模型之间的激活、抑制、依赖、冲突和组合关系；
- $\Phi$：能力与模型的语义参数或语义契约；
- $\Theta$：通过训练更新的路由、连接、可靠度和校准等数值参数。

一个显式模型节点表示为：

$$
M_i=(\Phi_i^M,\Theta_i^M)
$$

一个能力算子节点表示为：

$$
C_k=(\Phi_k^C,\Theta_k^C)
$$

### 3.1 语义参数 $\Phi$

语义参数规定模型或能力算子“是什么”和“负责什么”。对于显式模型，至少包括：

```text
模型身份与稳定 ID
机制定义
输入接口
输出接口
成立前提
适用边界
失效条件
可观察预测类型
允许的连接语义
反证与竞争性解释
```

语义参数最初由人定义或确认。语言模型可以根据结构性残差、公开证据和真实任务复盘提出 `new`、`amend`、`split`、`merge`、`contest` 或 `deprecate` 候选，但不能因文本更流畅或内部更一致就自动成为正式语义。

语义参数按离散版本演化，不通过普通数值优化器静默漂移。每次变更必须保留旧版本、候选理由、来源、测试、回归和回滚点。

### 3.2 数值参数 $\Theta$

数值参数控制能力与模型在特定情境中怎样参与网络运行，可以包括：

```text
能力选择与能力间跳转
能力—模型联合路由
激活概率
条件性连接权重
场景可靠度
置信度校准参数
触发与抑制阈值
推理路径策略
运行轮数与停止条件
模型调用成本
不同时间尺度下的权重
```

数值参数可以由人提供初始值、先验或安全边界，再由 Episode 数据持续训练。数值训练不得改变模型或能力算子的稳定身份、机制含义和接口语义。

### 3.3 七类能力算子

七类能力暂定为：

| 能力 | 核心操作 | 典型结构化输出 |
| --- | --- | --- |
| 定义 | 问题重构 | 目标、变量、边界、约束和未知量 |
| 解释 | 机制建模 | 因果机制、状态转移、预测和时间尺度 |
| 质疑 | 假设与反证 | 反例、竞争性解释、失效条件和需重跑步骤 |
| 求证 | 证据与不确定性 | 证据质量、验证计划、概率、区间和校准 |
| 创造 | 方案与迁移 | 新假设、新组合、新方案和模型候选 |
| 决策 | 权衡与行动控制 | 方案排序、行动、实验、退出条件和风险边界 |
| 学习 | 反馈与校准 | 误差诊断、信用分配、校准和更新信号 |

能力算子是可组合接口，不是固定流水线。同一个模型可以被不同能力调用，同一个能力也可以作用于多个模型形成临时子图。“学习”能力只负责产生任务内修正或跨 Episode 更新信号；训练器负责应用数值更新，语义治理流程负责决定语言模型提出的修改候选是否被接受。

### 3.4 连接

能力之间、能力与模型之间、模型之间的连接都必须保留显式语义。模型连接例如：

- `excites`：提高另一个模型的条件性激活；
- `inhibits`：降低另一个模型的激活或置信度；
- `requires`：另一个模型或条件是调用前提；
- `corrects`：校正另一模型的已知误用；
- `conflicts`：产生可区分的竞争性预测；
- `composes`：多个模型共同构成高阶机制；
- `specializes`：一个模型是另一模型的条件性特殊形式；
- `observes`：负责检查另一模型依赖的证据；
- `controls`：根据预测产生行动或实验。

连接类型和含义保持显式，连接强度可以依赖情境和目标：

$$
W_{ij}=g_{\theta}(M_i,M_j,x,G)
$$

模型组合可能存在不可约的高阶交互，因此数据结构应允许超边或临时计算子图，而不是永久限制为两两连接。

## 4. 推理时的网络动力学

给定任务情境 $x$、目标 $G$ 和当前共享状态 $h^t$，系统联合选择下一能力及其作用的模型子集：

$$
P(C_k,\mathcal{S}_M\mid x,G,h^t)
$$

能力算子运行后产生结构化输出并写回共享状态：

$$
o_t=C_k(\mathcal{S}_M,x,G,h^t),
\qquad
h^{t+1}=U(h^t,o_t)
$$

路由器随后学习继续、跳转、回退或停止：

$$
\pi(\text{next capability},\text{next models},\text{stop}\mid x,G,h^{t+1})
$$

一次推理不等于检索固定数量的模型，也不要求运行全部七类能力。目标运行方式是：

```text
情境、观察和目标进入共享状态
  -> 路由器联合选择能力算子和模型子集
  -> 能力调用模型并产生结构化输出
  -> 输出写回共享状态，激活或抑制沿条件性连接传播
  -> 网络形成任务特定的稀疏计算子图
  -> 跳转、循环、回退、请求信息或停止
  -> 聚合为可检验预测和行动建议
```

能力与模型输出不应只有自由文本。为了训练和评估，节点应尽量输出：

- 预测方向、概率或区间；
- 时间尺度；
- 关键中介变量；
- 可证伪信号；
- 建议行动或实验；
- 置信度与边界；
- 对其他模型的激活、抑制或挑战信号。

## 5. Episode：真实训练数据单元

真正的训练数据不是只有输入和一段看起来合理的分析，而是带有后续结果的决策或预测 Episode。最小链条是：

```text
情境与目标
  -> 观察及其质量
  -> 能力与模型版本、联合路由概率
  -> 能力路径、模型路径和连接
  -> 各模型的事前预测
  -> 网络最终预测与建议行动
  -> 实际行动
  -> 即时或延迟结果
  -> 外部变化与混杂因素
  -> 多维结果与归因状态
```

推荐的数据契约至少保留：

```json
{
  "episode_id": "ep-...",
  "context": {},
  "goal": {},
  "hard_constraints": [],
  "observations": {},
  "observation_quality": {},
  "model_versions": {},
  "activated_capabilities": [],
  "capability_path": [],
  "activated_models": [],
  "capability_model_bindings": [],
  "activation_probabilities": {},
  "activation_path": [],
  "conditional_edges": [],
  "model_predictions": [],
  "final_prediction": {},
  "recommended_action": {},
  "actual_action": {},
  "expected_horizon": {},
  "actual_outcome": {},
  "outcome_quality": {},
  "confounders": [],
  "utility_vector": {},
  "attribution_status": "resolved | partial | unknown"
}
```

推荐行动与实际行动必须分开；当执行与建议不同、结果不可观察或存在重大混杂时，不得把结果直接归因于模型网络。

## 6. 数值参数的快速学习回路

在固定语义版本 $\Phi^v$ 下，系统可以较频繁地更新数值参数：

$$
\Theta_{t+1}=\operatorname{Train}(\Theta_t,E_{1:t}\mid G,K,\Phi^v)
$$

可用方法包括监督学习、Contextual Bandit、强化学习、贝叶斯更新、可微组件的梯度下降和离线策略评估。方法由数据量、反馈延迟、可观测性和行动风险决定，不把任何单一训练方法写成协议要求。

优先训练：

1. 模型激活概率；
2. 模型在不同场景中的可靠度与校准；
3. 条件性连接强度；
4. 推理顺序、轮数和停止条件；
5. 稀疏性和运行成本。

边和节点的贡献不能仅由共同出现频率决定。最低要求是进行模型级、边级或组合级消融：

$$
\operatorname{Contribution}_{ij}
=
L(\text{without edge}_{ij})-L(\text{full network})
$$

由于模型可能存在高阶交互，单边消融只能作为线索；关键组合还需要条件性消融、随机子集比较或近似 Shapley 分析。低频但覆盖高损失风险的模型不得仅因平均收益低而被削弱。

## 7. 语义参数的慢速演化回路

语义演化只由持续、可区分的结构性残差触发：

```text
积累失败或校准偏差
  -> 按情境、目标、模型版本和时间尺度聚类
  -> 排除路由、参数、执行、环境与测量解释
  -> 确认现有语义无法表达的共同残差
  -> 语言模型生成语义修改候选
  -> 独立来源与竞争性机制检查
  -> 历史回放和未参与生成的保留集测试
  -> 影子运行与回归监测
  -> 按策略接受、拒绝、暂缓或回滚
```

可以表示为：

$$
\widehat{\Phi}^{v+1}
=
\operatorname{LLMPropose}(\Phi^v,R,E,K)
$$

其中 `R` 是结构性残差。候选只有在独立评估通过后才成为新语义版本：

$$
\Phi^{v+1}
=
\begin{cases}
\widehat{\Phi}^{v+1}, & \text{通过证据、保留集、反例、稳定性和风险闸门}\\
\Phi^v, & \text{证据不足、退化或不可归因}
\end{cases}
$$

语言模型是候选生成器，不是最终证据来源或唯一裁判。语言模型生成候选、生成测试并评价自己不能构成独立验证。

## 8. 训练目标与约束

网络可以同时优化预测、决策、校准、复杂度和稳定性：

$$
L=
\lambda_1L_{prediction}
+\lambda_2L_{decision}
+\lambda_3L_{calibration}
+\lambda_4L_{complexity}
+\lambda_5L_{stability}
$$

但 `λ` 不应成为跨任务永久固定的全局价值权重。它们必须受当前目标 $G$ 和治理策略 `K` 条件化。隐私、来源完整性、不可逆风险上限、禁止自动修改的资产和最低校准要求应作为硬约束，不能被其他指标的收益抵消。

结果优先保存为多维向量，而不是过早压缩成一个 `utility` 标量。调用次数、模型数量、采纳率、文档长度或单一自动总分均不能自动决定模型命运。

## 9. 防止退化为规则引擎或黑箱网络

### 防止退化为规则引擎

- 适用性、可靠度、连接强度和路径策略必须能由 Episode 训练；
- 人只定义或确认语义契约和安全边界，不手工指定每个场景的完整路径；
- 连接强度由增量结果检验，而不是由直觉或共同出现频率固定；
- 允许网络根据目标和情境形成不同的稀疏子图。

### 防止退化为不可解释黑箱

- 数值训练不能静默改变模型身份、机制或接口；
- 每次推理记录模型版本、激活概率、路径和结构化输出；
- 语义修改必须产生可读差异、证据、测试和版本历史；
- 不把全部模型语义重新压缩进无法回引的端到端向量；
- 真实结果、保留集和外部证据高于语言合理性。

## 10. 分阶段实现

### Phase 0：统一接口与基线

- 选择 12–20 个机制差异明显的模型节点；
- 固定七类能力算子的初始语义接口；
- 固定模型语义版本并定义结构化输入输出；
- 建立 Episode 数据契约、版本和回放能力；
- 比较规则检索、LLM 直接选择和无训练网络基线。

### Phase 1：可训练路由

固定能力与模型语义以及主要连接类型，只训练：

- 能力选择和能力间跳转；
- 能力—模型联合路由；
- 激活概率；
- 场景可靠度；
- 条件性连接强度；
- 停止条件；
- 置信度校准。

### Phase 2：条件性子网络

让不同场景共享能力与语义模型，但学习不同的能力—模型组合、连接、阈值和路径，例如产品决策、软件架构、组织管理和个人决策子网络。

### Phase 3：结构和语义可塑性

积累足够真实、延迟和可归因结果后，再允许自动提出和评估：

- 新建；
- 修改；
- 拆分；
- 合并；
- 争议化；
- 废弃模型。

所有结构和语义变化必须经过历史回放、未参与生成的保留集、反例测试、影子运行和可回滚部署。

## 11. 与当前仓库的关系

当前仓库中的模型卡提供显式模型 $\Phi^M$ 的初始语义资产；README 中的七类能力提供能力算子 $\Phi^C$ 的候选接口；关系索引提供部分候选连接；分析协议提供尚未训练的能力—模型路由和挑战基线；模型演化协议提供 Episode、证据、归因和版本治理的安全基线。

当前 proposal 与显式接受流程仍是第一阶段实现。目标架构是在用户预先设定的权限与风险策略内自动训练 $\Theta$，并由语言模型提出 $\Phi$ 的候选修改，再由真实结果、独立证据和测试决定是否接受。身份、价值函数、原则和长期目标属于外部治理输入，不是训练器可自行改写的参数。
