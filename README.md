# LollaNet

LollaNet 是一个本地、可审计、由用户控制的认知层。它在任务需要时，调用用户确认的个人资料、长期目标、行动准则、思维模型与证据，帮助 AI 理解问题、检验假设并形成行动。用户决定哪些信息进入分析，也决定哪些结果值得长期保存。

LollaNet 从查理·芒格的多元思维模型出发，并吸收学科研究、历史机制、失败案例、阅读与实践观察。每次分析只选择少量能改变问题定义、预测或行动的模型，并检查它们的证据、边界、反例和可验证信号。

项目处于 MVP 验证期。首轮 10 题盲评达到预设的探索门槛，支持 LollaNet 可能改善短期回答质量。现有结果来自单次、同模型族测试，尚未证明跨模型稳定性或长期决策效果。下一阶段将通过独立复现、模型消融和 30/90 天复盘继续检验。

## 为什么需要多元思维模型

人的收入、声誉、身份或组织指标依赖某个结论时，激励可能偏置证据搜索、解释和建议，形成[激励导致的偏见](01-Models/学科知识/心理学/激励导致的偏见.md)。人也容易把最熟悉的专业、工具或解释框架套到所有问题上，形成“铁锤人倾向”。两者还会相互强化：一个人不仅手里只有一把锤子，激励还可能让他更愿意相信眼前的一切都是钉子。

LollaNet 试图通过以下机制降低这两类风险：

- 对复杂任务执行芒格式双轨分析：先用理性分析轨检查事实、利益、概率和机制，再用心理误判审计轨检查这个判断如何形成；
- 先检查谁从某个结论中获益、谁承担错误后果，把激励结构与证据质量分开分析；
- 从不同学科和机制中只选择 3–7 个真正改变假设、预测或行动的非重复模型，避免由单一框架垄断解释；
- 主动寻找反证、竞争性机制、模型冲突、适用边界和失效条件；
- 不按模型数量投票，而是比较因果机制、证据质量和能够区分不同解释的未来观察；
- 通过可观察预测和延迟复盘，检查当初的判断是否只是受到利益、熟悉感或叙事吸引。

这套方法可以帮助暴露和校正偏见，但不能保证消除偏见。模型选择本身也可能受到激励和“铁锤人倾向”影响，因此来源回引、挑战路线、人工审议和长期复盘仍然不可省略。

## 核心边界

- 当前任务默认留在原来的聊天、仓库或应用中，不会自动进入长期记录。
- AI 只读取会显著改变当前判断的最小私人上下文。
- 复杂任务只保留真正改变假设、预测或行动的非重复模型；不按模型数量投票。
- AI 可以提出模型或个人资料修改建议，但不能静默修改正式认知资产。
- 公共框架不能包含用户画像、真实决策、私人对话、未公开项目或专有资料。

## 一次分析怎么运行

```text
当前任务
    ↓
建立临时任务模型，确认目标、约束、未知量和风险
    ↓
按需读取最小私人上下文
    ↓
从模型、记忆和挑战三个方向检索可回引材料
    ↓
去重、处理冲突，检查基础概率、证据质量和时间尺度
    ↓
执行芒格式双轨分析：理性分析轨 -> 心理误判审计轨
    ↓
若发现重大判断形成风险，回到受影响的理性步骤复查
    ↓
给出当前判断、成立条件和可验证的下一步
    ↓
用户选择是否保存项目、决策、证据或修改提案
```

简单事实查询、格式转换、机械改写和低风险执行可以直接完成，不必启动多路召回。完整规则见 [LollaNet Analysis Protocol](04-Prompts/LollaNet%20Analysis%20Protocol.md)。

这里的“双轨”是同一分析中的两趟检查，不是两个 Agent 分别给结论，也不按两轨投票。心理误判风险只能触发复查，不能单独证明一个结论错误。

## 经验驱动的自动模型演化架构

目标形态的 LollaNet 暂分为四层：

1. **任务状态层**：保存情境、目标、观察、约束、不确定性和当前工作状态；
2. **能力算子层**：提供定义、解释、质疑、求证、创造、决策和学习七类可组合认知操作；
3. **显式模型网络层**：保存具有明确机制、接口、边界和版本的认知模型节点及其条件性连接；
4. **结果学习与演化层**：比较事前预测、行动和真实结果，训练数值参数，并在出现结构性残差时触发语义修改候选。

这四层不是固定流水线。共享认知状态和可训练路由器贯穿各层，使能力算子能够根据任务选择、组合和反复调用显式模型。

LollaNet 必须区分两种变化：

- **世界转移**：模型描述世界状态在行动、事件和条件影响下可能怎样变化；
- **模型更新**：系统根据经验自动完善模型内容、适用边界、模型关系和调用策略。

世界转移模型可以表示为：

$$
P(S_{t+1}\mid S_t,A_t,C_t)
$$

但并非所有模型都是世界转移模型。LollaNet 还需要观察与推断、评价与目标、控制与行动、元认知与挑战等不同职责的模型。

目标架构的可计算核心表示为：

$$
\mathcal{N}=(V_C,V_M,E;\Phi,\Theta)
$$

其中，$V_C$ 是七类能力算子节点，$V_M$ 是显式认知模型节点，$E$ 是能力与模型之间的条件性连接。

- $\Phi$ 是语义参数或语义契约，规定节点的身份、职责、机制、输入输出、成立前提、适用边界和可证伪预测；
- $\Theta$ 是数值参数，控制能力与模型的选择、路由、激活强度、连接权重、可靠度、置信度、推理顺序和停止条件。

LollaNet 的核心数值学习问题是：

$$
\boxed{
\text{给定情境和目标，学习哪些显式模型应当以什么顺序、强度和结构共同工作}
}
$$

当数值训练无法消除稳定的结构性残差时，系统进入语义演化回路：

$$
\boxed{
\text{由语言模型提出语义修改候选，再由真实结果和测试决定是否接受}
}
$$

数值参数通过高频、连续、可回滚的训练更新；语义参数通过低频、离散、版本化的提案更新。语言模型负责生成候选，不负责证明候选正确。

人负责设定目标、价值约束、自动化权限、证据门槛、风险等级和最终否决权；系统负责在这些边界内持续产生、验证、部署或回滚模型更新。身份、价值函数、原则和长期目标不属于经验优化器可以自行改写的参数。

详细的网络表示、Episode 数据、信用分配、结构演化和验证流程见 [可训练认知模型网络架构](07-Docs/trainable-cognitive-model-network.md)。当前仓库仍处于人工提案与显式接受的安全实现阶段。

## 快速开始

### 直接试用

如果当前 Codex 环境已安装参考 Skill，可以直接调用：

```text
$lollanet-analyze <需要分析的问题>
```

简单任务会跳过复杂召回。其他 AI 工具可以按照 [LollaNet Analysis Protocol](04-Prompts/LollaNet%20Analysis%20Protocol.md) 实现相同流程；协议不依赖特定厂商、向量数据库或固定模型清单。

### 启用私人认知层（可选）

```bash
git clone https://github.com/qkdawn/LollaNet.git
cd LollaNet
python 06-Scripts/init_private.py
```

初始化脚本只补充缺失文件，不覆盖已有私人内容；`private/` 已加入 `.gitignore`。用 Obsidian 打开仓库根目录，从 [LollaNet Dashboard](00-Start/Dashboard.md) 进入。

私人资料按语义分开保存：

| 文件 | 作用 |
| --- | --- |
| `User Profile.md` | 经历、能力、资源和现实约束 |
| `Value Function.md` | 用户确认的价值、硬约束和内部张力 |
| `Principles.md` | 在具体条件下愿意如何行动 |
| `Long-term Goals.md` | 服务价值、可替换的目标状态 |
| `Current Focus.md` | 当前 6–12 周的资源配置和实验 |

观察记录和复盘是证据，不会自动变成身份、价值、准则或目标。当前焦点是可撤回的短周期配置，不是新的终极价值。

## 模型治理

每张正式模型卡都有稳定 ID、版本和状态：`candidate`、`active`、`contested`、`deprecated`。模型更新操作包括 `new`、`amend`、`split`、`merge`、`contest` 和 `deprecate`。

当前仓库使用人工审阅的 proposal 流程作为第一阶段安全参考实现：接受提案和修改正式模型是两个独立动作。目标架构则由自动模型更新器生成候选、运行验证，并按照用户预先批准的风险策略自动接受、暂缓、拒绝、部署或回滚；超出权限或风险阈值的变化再升级给用户，而不是要求人手工处理每次更新。

当前模型提案使用 `proposed`、`accepted`、`rejected`、`deferred` 状态。创建新模型时，需要引用已经接受的提案：

```bash
python 06-Scripts/create_model.py "模型名称" \
  --source-category 学科知识 \
  --discipline 数学 \
  --subdiscipline 通用 \
  --proposal mp-accepted-proposal-id
```

废弃模型保留历史。模型卡必须说明机制、适用边界、反证、失效条件和可观察预测；详细数据契约见 [PROJECT_SPEC](PROJECT_SPEC.md)。

## 未来方向

未来重点是把模型库转化为可被不同业务 Skill 按需调用的通用认知能力，而不是让模型直接生成论文、算法或项目报告：

```text
思维模型库 -> 能力算子层 -> 算法、研究、项目和产品 Skill
```

### 七类能力算子层

七类能力暂定为：**定义**（问题重构）、**解释**（机制建模）、**质疑**（假设与反证）、**求证**（证据与不确定性）、**创造**（方案与迁移）、**决策**（权衡与行动控制）、**学习**（反馈与校准）。未来它们将作为 LollaNet 神经网络中的**能力算子节点**，而不是七个依次执行的固定步骤。

显式模型节点回答“使用什么机制思考”，能力算子节点回答“现在对问题、模型和证据执行什么认知操作”。同一个模型可以被不同能力调用，同一个能力也可以同时组合多个模型。例如，“解释 × 反馈回路”用于形成机制预测，“质疑 × 反馈回路”用于检查伪循环和替代解释，“决策 × 反馈回路”用于寻找干预点。

未来网络可以写成异构节点集合：

$$
V=V_C\cup V_M
$$

其中 $V_C$ 是七类能力算子节点，$V_M$ 是显式认知模型节点。路由器联合学习：

$$
P(C_k,\mathcal{S}_M\mid x,G,h_t)
$$

即在当前情境、目标和工作状态下，下一步使用哪个能力、作用于哪些模型、以多大强度运行，以及完成后返回定义、继续求证、进入决策还是停止。能力之间允许跳转、循环和回退，不要求每次任务都运行全部七类能力。

“学习”具有双重时间尺度：任务内负责根据新证据修正当前状态，跨 Episode 负责比较预测与结果、生成信用分配和校准信号。真正的数值更新由训练器执行，语义修改仍由语言模型提出候选并接受现实结果与测试治理，避免“学习能力”同时拥有提案权和自我批准权。完整设计见 [可训练认知模型网络架构](07-Docs/trainable-cognitive-model-network.md)。

### 跨层认知控制：发散—收敛与双轨审计

未来网络还需要两种贯穿四层的运行时控制机制。它们不是新的固定层，也不是两个普通模型节点：

| 机制 | 网络位置 | 主要职责 |
| --- | --- | --- |
| 发散—收敛探索模式 | 跨层路由状态 | 控制认知搜索的宽度、分支和收束时机 |
| 芒格式双轨分析 | 跨层审计回路 | 分别检查外部事实判断和判断形成过程 |

#### 发散—收敛探索模式

路由器维护当前搜索状态：

$$
m_t\in\{\text{diverge},\text{converge}\}
$$

当问题定义、核心对象、用户价值、约束或成功标准仍不稳定时，网络进入发散状态，优先调用定义、创造、解释和质疑能力，并从不同机制中形成有区分度的竞争性问题框架。发散的目标不是无限增加想法，而是避免把暂定表述或单一技术叙事过早当成唯一问题定义。

当对象、目标、约束、候选行动和成功标准已经足以比较时，网络进入收敛状态，减少无增量分支，优先调用求证、质疑、决策和学习能力，形成可检验预测、方案比较、行动边界和停止条件。若求证或审计发现问题定义不成立，路由器可以局部返回发散，而不是被第一次收敛永久锁定。

#### 芒格式双轨审计回路

双轨分析应实现为同一网络上的两次有顺序检查，而不是两个 Agent、两个独立答案或多数票：

```text
理性分析子图
  -> 检查事实、利益、概率、因果机制和机会成本
  -> 形成暂定判断
心理误判审计子图
  -> 检查激励、熟悉框架、确认偏误和过度自信怎样影响判断形成
  -> 若发现重大扭曲风险，定位受影响步骤并触发定向重跑
  -> 否则保留暂定判断并结束审计
```

心理误判风险不能单独证明一个结论错误。审计轨只能生成结构化风险信号、受影响步骤和重跑条件；最终结论仍必须回到证据和理性分析轨重新检验。这样可以把双轨分析表示为：

$$
\text{Rational Subgraph}
\rightarrow
\text{Audit Subgraph}
\rightarrow
\text{Targeted Rerun}
$$

两种控制可以组合为网络状态：

$$
z_t=(m_t,r_t),
\qquad
r_t\in\{\text{rational},\text{audit},\text{rerun}\}
$$

未来路由器不仅学习下一能力和模型子集，也学习何时发散、何时收敛、何时进入心理审计、审计后重跑哪个步骤以及何时停止。结果学习与演化层再根据真实 Episode 检查这些模式切换和审计触发是否真正改善预测、校准、行动与长期结果。现行流程边界见 [LollaNet Analysis Protocol](04-Prompts/LollaNet%20Analysis%20Protocol.md)。

### 外部认知输入与模型迭代

这是待验证能力，不代表当前已经实现。拟议链路是：

```text
用户选择的信息源
    -> Horizon 等 RSS 收集层
    -> 内容获取与转换层
    -> 私人暂存区
    -> 模型迭代意见日报
    -> 人工决定：忽略、保留证据、阅读笔记或提出修改提案
```

RSS 条目、文章和案例先是输入材料，不会自动成为正式模型。Horizon 和内容转换工具的接口、授权、部署方式、输出格式和维护状态仍需验证。日报、模型提案和正式模型更新保持独立步骤。详细边界见 [external-input-loop.md](07-Docs/plans/external-input-loop.md)。

相关知识来源可按“来源大类 -> 具体领域 -> 正式模型”组织：时势信号、哲学模型、历史机制、他人失败和学科知识。原始文章、研究和案例只能作为输入材料或证据；只有确认其改变了假设、预测或行动后，才关联已有模型或形成修改提案。完整分类契约见 [PROJECT_SPEC](PROJECT_SPEC.md)。

### 个人资料驱动的模型应用与迭代

这也是待验证能力，不代表当前会自动记录或个性化所有任务。公共模型保持通用机制、证据与边界；在用户明确授权且任务相关时，最小私人上下文可以影响模型选择、参数、风险阈值和行动优先级，但不能改写公共模型事实。用户选择保存的真实调用结果默认进入私人评估或项目复盘，并且只能在人工审议 proposal 后影响私人适配或正式模型版本。详细设计、隐私闸门和分阶段验证见 [personalized-model-evolution-loop.md](07-Docs/plans/personalized-model-evolution-loop.md)。

### 个人资料与行动规划

在用户明确授权后，已确认的个人资料、目标、当前焦点和项目约束可以生成候选待办和番茄钟项目：

```text
个人资料与当前焦点 -> 候选行动 -> 用户确认 -> 待办与番茄钟 -> 时间反馈与复盘
```

它用于落实已经选择的方向，不替用户创造新的价值或永久优先级。任务、日程和专注记录属于私人数据，支持暂停、删除和人工覆盖。

### 审稿式项目与算法研究

未来可以提供从评审者立场审视论文、研究计划和技术项目的 Skill，检查主张、机制、证据、替代解释、基线、可复现性和结论边界；也可以辅助算法研究发现不变量、反例、证明义务和基准实验。它们辅助形成可追溯的审计意见和研究路线，不替代领域专家、正式同行评审、正确性证明或实验结果。

### 多元思维模型与诗歌创作

未来可以探索用多元思维模型辅助诗歌创作。模型不替代诗人的经验、感受和语言选择，而是从意象生成、概念张力、视角转换、结构约束、反向思考和跨学科隐喻等方向提供可组合的创作刺激：

```text
主题、经验或情绪
    -> 选择少量能够产生新张力的异质模型
    -> 生成意象、关系、视角和形式约束
    -> 写作、删改与朗读检验
    -> 人决定作品是否成立
```

诗歌创作不按调用模型的数量评价，也不把模型名称机械堆进诗句。需要验证的是，多元模型是否真正增加了意象的新鲜度、语言的准确性、情感的真实性和作品内部的张力；引用既有作品、风格或材料时，仍须遵守来源和著作权边界。
